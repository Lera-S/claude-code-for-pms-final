# 02 · Super Hearing — prompts

**Context:** You joined Rook two weeks ago as PM on Dispatch.
Release 4.2 shipped on 12 August, just before you arrived, and
landed badly. Last session you built a context file and met the
company.

You still do not know what actually went wrong.

At the end of the session, ask Claude Code to save the prompts you
wrote yourself below — not the starter prompt. The closing slide has
the exact prompt to paste. By Module 6 this file is a prompt library
built from your own questions.

---

### 1.

highlight the common pain points between these 4 user interviews

### 2.

what is the expected callout duration that responder got used to and expects?

### 3.

were users notified via release notes or any other channels about the changes in the callaouts? their volume and style?

### 4.

Did anyone say something that nobody else mentioned?

### 5.

analyze if there is anything in common between those individual issues?

### 6.

Based on the user interviews clarify is it fair assumption that 60 seconds cut was unexpected by users and also change in the text and sound was unexpected that's why they were missing the notifications?

### 7.

I should notify my team about what is the trouble with 4.2 release based on the collected interviews. Apparently it is shortened timeout and absence of the acknowledgement. Confirm and suggest if there is anything more to add to the conclusion for the team. Start the conclusion as Based on the interviews, the trouble with 4.2 is ___.

### 8.

Read everything in 00-rook/feedback/tickets/. Same treatment as before: group them, tell me how many are in each group, and quote one line from each.

### 9.

Who filed these? Give me a list of names and how many of them filed each.

### 10.

are those tickets which are part of the release 4.2? or opened bugs after the release 4.2

### 11.

are there any tickets which were part of the release 4.2 might be relevant to the issues which were caused after this release and those 25 post release tickets?

### 12.

when those tickets were submitted compared to the 4.2 release date?
were any of those tickets pushed to production or there was nothing fixed since the release?

### 13.

were the same issues repeated every week in the tickets or there is any pattern related to the type of the issue mainly raised every week?

### 14.

You've now read both folders. Where do they disagree? What's loud in the interviews but rare in the tickets, and what's all over the tickets that nobody brought up in the interviews?

### 15.

If both piles are telling the truth, how can they both be right?

### 16.

create a graph per issue highlighting what issue was surfaced from the interviews and which was surfaced from tickets
